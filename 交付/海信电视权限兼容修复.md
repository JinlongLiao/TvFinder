# 海信电视权限兼容修复

日期：2026-09-23。

## 已确认的问题

- 用户截图显示：Hisense / VIDAA_TV，Android 11 / API 30，固件 `RP1A.200720.011 release-keys`，TV Finder 0.1.0，文件访问权限未开启。
- 原 `MainActivity.onCreate` 只建立页面，未主动发起权限引导；权限申请依赖首页或侧栏的手动入口。
- 原提示仅在应用专属、通用“所有文件访问”页面均抛出 `ActivityNotFoundException` 或 `SecurityException` 时展示。截图不能进一步区分缺少页面还是访问被拒绝。
- Android 11 且 targetSdk ≥ 30 时，普通 `WRITE_EXTERNAL_STORAGE` 不会额外授予文件访问能力，不能用普通权限弹窗替代所有文件访问授权。

## 本次修改

- 未授权用户首次启动自动看到用途说明，确认后进入系统授权；取消、返回、重建和后续启动不重复自动提示，保留手动入口。
- Android 11+ 依次尝试应用专属、通用所有文件访问页；均失败后明确提示，并提供“打开应用设置”按钮。
- 用户点击后依次尝试应用详情、应用列表、系统设置；全部失败时提供遥控器手动操作及诊断说明。
- 仍以 `Environment.isExternalStorageManager()` 判断 Android 11+ 授权状态，不把普通媒体权限或成功打开设置页当作授权成功。
- 设置页启动失败日志包含动作、包名、设备型号、SDK、固件、异常类型、message 和完整堆栈，不记录鉴权凭据。
- 同步中英文文案，补充首次启动和入口缺失回归测试。

已检索公共 Java 工具库；本次涉及 Android Activity、Intent、SharedPreferences 和系统权限 API，没有可复用的对应公共能力，无需引入服务端工具依赖。

## 真机验收步骤

1. 覆盖安装修复包后启动，未授权时应出现首次用途说明；选择开启权限。
2. 若特殊授权页缺失，选择“打开应用设置”，查找 TV Finder 的所有文件访问或文件管理权限。
3. 授予权限后返回应用，应显示权限已开启；再验证内部共享存储和 USB 的实际浏览、复制、新建、重命名、移动与删除。
4. 取消授权后退出并重新启动，不应反复弹出引导；手动权限入口应仍可使用。
5. 如果所有设置里都没有对应开关，记录设备信息和 `TvFinder` 标签的系统日志。仅增加设置回退不能保证该固件允许授予权限；需据真机证据继续适配。

## 本轮验证结果

- 使用 JDK 17、compileSdk 34，`testDebugUnitTest assembleDebug lintDebug` 成功。
- 32 项单元测试通过，其中新增 Android 11 权限测试 9 项：首次引导、取消后重启、已有权限、专属页、通用页、应用详情、应用列表、系统设置、所有入口缺失及诊断日志。
- 将 HEAD 中的旧 MainActivity 放入独立临时项目，用同一首次启动测试验证，得到预期断言失败：“首次启动应显示文件访问授权引导”。当前工作区源码未被覆盖。
- Lint：0 错误、8 警告；未隐藏警告。构建期间外部新增的 `buildToolsVersion 29.0.2` 与 `ndkVersion` 配置保留；AGP 明确忽略过低的 Build Tools 配置，实际采用 34.0.0。
- 中英文资源 131 项键一致；UTF-8、LF、尾随空白、末尾换行及 `git diff --check` 检查通过。
- APK v2 签名验证通过；包名 `io.github.jnlongliao.tv.finder`，版本 `0.1.0` / `1`，minSdk 26、targetSdk 34。使用本机 debug 签名，未验证与电视上旧包的签名是否相同。
- APK：`TV-Finder-0.1.0-权限修复-debug.apk`；校验文件：`权限修复-SHA256SUMS.txt`。
- 测试运行时下载需要继承本机 Gradle 代理，使用临时 init script 转发 JVM 的代理 host/port 设置；代理信息没有写入项目。
