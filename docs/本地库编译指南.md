# 本地库编译指南

本文说明如何在 Windows、macOS、Linux 上从仓库源码构建包含 USB FAT/exFAT 本地库的 Android APK。首次构建需要联网下载 Gradle、Android 依赖和指定 SDK 组件；后续可在依赖已缓存时离线构建。以下命令均在仓库根目录运行。

## 构建链与源码

```text
Gradle Wrapper 8.9 → Android Gradle Plugin 8.5.2
                    → Android SDK 34 + NDK 21.4.7075529 + CMake 3.22.1
                    → app/src/main/cpp/CMakeLists.txt
                    → libtvfinder_fatfs.so（arm64-v8a、armeabi-v7a）
                    → APK
```

`app/build.gradle` 用 `externalNativeBuild.cmake` 指向仓库中的 `CMakeLists.txt`，并固定 NDK、CMake 版本和两个 ARM ABI。Gradle 会自动调用 NDK 的交叉编译工具链，再将生成的 `.so` 放入 APK；**无需在开发电脑上手工运行 CMake、安装独立的 GCC/Clang、下载预编译 `.so`，也无需先编译 C 文件**。Windows 电脑同样可以交叉编译供 Android 11 电视运行的 ARM 库。x86/x86_64 模拟器不在当前 ABI 范围内。

本地代码位置与职责：

| 路径 | 内容 |
| --- | --- |
| `app/src/main/cpp/fatfs/ff.c`、`ff.h`、`ffunicode.c`、`diskio.h` | 随仓库提供的 FatFs R0.16；`ff.c` 合入上游 patch-1、patch-2。 |
| `app/src/main/cpp/fatfs/ffconf.h` | 本项目的 FatFs 配置，启用 exFAT、长文件名和 UTF-8。 |
| `app/src/main/cpp/usb_fatfs_bridge.c` | JNI 与 FatFs 的磁盘读写适配。 |
| `app/src/main/java/io/github/jnlongliao/tv/finder/UsbScsiBlockDevice.java` | Android USB Host 到 USB Mass Storage/SCSI 块设备的传输。 |
| `app/src/main/java/io/github/jnlongliao/tv/finder/FatFsVolume.java` | 加载 `tvfinder_fatfs` 本地库并提供文件操作入口。 |

FatFs 上游：[项目与 R0.16 下载](https://elm-chan.org/fsw/ff/)、[官方补丁](https://elm-chan.org/fsw/ff/patches.html)；原始许可保留在 `app/src/main/cpp/fatfs/LICENSE.txt`。修改第三方源码或配置时需保留上游版权和许可，并同步检查中英文第三方声明。当前构建不从网络下载 FatFs C 源码，克隆仓库即可取得。不要将 `app/build/`、`app/.cxx/`、本机 SDK 路径或临时下载缓存提交到仓库。

## 一次性环境准备

1. 安装 **JDK 17**，并确保 `java -version` 和 `JAVA_HOME` 指向 JDK 17。项目使用 Gradle Wrapper，无需单独安装 Gradle。
2. 安装 Android Studio，或至少安装 Android SDK Command-line Tools。确定 Android SDK 目录，设置 `ANDROID_HOME`；也可以在仓库根目录建立仅供本机使用的 `local.properties`，写入 `sdk.dir`。该文件已被 Git 忽略，**不要把电脑上的绝对 SDK 路径写进仓库的构建脚本**。
3. 通过 SDK Manager 安装 `platforms;android-34`、`build-tools;34.0.0`、`ndk;21.4.7075529`、`cmake;3.22.1`，并阅读、接受所需 Android SDK 许可。命令行工具自身需事先安装在 SDK 的 `cmdline-tools/latest/` 目录。AGP 在许可已接受且网络可用时也可按配置自动下载缺少的 NDK/CMake。

Windows PowerShell 示例（先在自己的环境中设置正确的 SDK 路径）：

```powershell
$env:ANDROID_HOME = 'C:\path\to\Android\Sdk'
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --licenses
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" 'platforms;android-34' 'build-tools;34.0.0' 'ndk;21.4.7075529' 'cmake;3.22.1'
.\gradlew.bat :app:assembleDebug
```

macOS / Linux 示例：

```bash
export ANDROID_HOME="/path/to/Android/Sdk"
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --licenses
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" 'platforms;android-34' 'build-tools;34.0.0' 'ndk;21.4.7075529' 'cmake;3.22.1'
bash ./gradlew :app:assembleDebug
```

如果 Android Studio 已安装上述组件并配置了 SDK 位置，日常“一键构建”只需最后一行 Gradle 命令。`local.properties` 的 `sdk.dir` 是单机设置，换电脑后重新配置；FatFs 源码、Gradle、CMake 配置都已在仓库。`--offline` 仅适用于所有依赖和 SDK 组件已经在该电脑缓存的情形；首次构建不要加它。

## 产物与校验

`assembleDebug` 成功后 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，应用 ID 为 `io.github.jnlongliao.tv.finder`。临时 `.probe` 后缀和探针 Activity 已从源码移除。`assembleRelease` 同样使用该应用 ID：仅当本机存在 `.signing/release.properties` 及其指向的密钥时才签名；否则生成未签名 APK，不能直接安装。发布密钥和密码文件已由 `.gitignore` 排除，需自行安全备份，并在其他电脑恢复到对应路径才能构建相同签名的更新包。不要用不同电脑生成的 debug 签名 APK 直接覆盖已安装包；Android 会因签名不一致拒绝更新。

本机签名配置文件示例（真实密码和密钥绝不提交 Git）：

```properties
storeFile=.signing/tv-finder-release.p12
storePassword=<your-private-password>
keyAlias=tvfinder
keyPassword=<your-private-password>
```

可用 JDK 自带的 `jar` 检查 APK 是否同时包含两个本地库：

```powershell
& "$env:JAVA_HOME\bin\jar.exe" tf app\build\outputs\apk\debug\app-debug.apk | Select-String 'lib/(arm64-v8a|armeabi-v7a)/libtvfinder_fatfs.so'
```

```bash
"$JAVA_HOME/bin/jar" tf app/build/outputs/apk/debug/app-debug.apk | grep -E 'lib/(arm64-v8a|armeabi-v7a)/libtvfinder_fatfs\.so'
```

应看到两个 ABI 各一条记录。`app/build/intermediates/cxx/` 和 `app/.cxx/` 中的文件是 Gradle 中间产物，不是需要复制到新电脑的源码。`assembleDebug` 证明编译与打包成功，不证明目标电视的 USB 权限、SCSI 兼容性或 exFAT 读写已经通过实机验证。

## 常见失败

| 报错或现象 | 检查方向 |
| --- | --- |
| `SDK location not found` | 设置 `ANDROID_HOME`，或在本机 `local.properties` 写 `sdk.dir`。 |
| `License for package ... not accepted` | 用同一 SDK 下的 `sdkmanager --licenses` 阅读并接受许可，然后重试。 |
| 找不到 NDK/CMake 或 `source.properties` 缺失 | 确认装的是上文固定版本；不完整的 SDK 组件应通过 SDK Manager 重新安装。 |
| `CXX1429` 且 `CMakeError.log` 提示 `CMakeTmp/testCCompiler.c` 或 `cmTC_*.dir` 不存在 | 这是编译器探测期间临时文件消失；先停止 Android Studio 与命令行对同一工作区的并发构建，再单独运行 `bash ./gradlew :app:assembleDebug`。若仍失败，保留 `app/.cxx/` 与 `app/build/intermediates/cxx/` 下的详细日志继续定位，不要仅凭 `CXX1429` 更换 NDK。 |
| `Unsupported class file major version`、JDK 不匹配 | 检查 `java -version`、`JAVA_HOME` 与 Android Studio 的 Gradle JDK，使用 JDK 17。 |
| Gradle 下载失败或 TLS/代理错误 | 检查当前电脑到 `services.gradle.org`、Google Maven、Maven Central 和 Android SDK 下载源的连接，再重新运行；不要把本机缓存路径写入项目。 |
| `No implementation found` / `UnsatisfiedLinkError` | 先检查 APK 内对应 ABI 的 `.so`，再核对电视的 CPU ABI；当前不提供 x86/x86_64 库。 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 已安装包与新包签名不同；核对包名与签名后再决定如何处理已安装应用，不要盲目卸载以免丢失应用数据。 |

参考 Android 官方的 [NDK/CMake 安装指南](https://developer.android.com/studio/projects/install-ndk)、[Gradle 连接本地构建指南](https://developer.android.com/studio/projects/gradle-external-native-builds) 和 [AGP 8.5 兼容要求](https://developer.android.com/build/releases/agp-8-5-0-release-notes)。
